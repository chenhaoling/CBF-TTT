# 写入—读取链路检查（2026-10-03 执行，10-05 归档）

## 结论

原始 BF16 dev 结果逐条复现，最大误差 0；双生差异能够传播到查询 hidden。仅将最终词表投影改成 FP32，或将双生差异按固定倍率放大，都没有提高事实识别准确率。因此未发现能解释失败的“完全相同缓存”或“记忆完全未被读取”问题；当前证据仍不足以支持有效的事实记忆。

完整 FP32 读取也完成且准确率仍为 12.5%。但 checkpoint 原始存储 dtype 的额外核验请求两次遭自动审批超时，均未执行。两条路径从相同 checkpoint 分别按 BF16/FP32 加载，尚未逐值验证参数值完全一致，所以完整 FP32 对照只能作为读取配置敏感性结果，不能把所有差异严格归因于算术精度。仅 head FP32 对照共享完全相同的 BF16 backbone 和 hidden，没有这项混杂。

## 范围与方法

执行前协议：[`WRITER_PATH_DIAGNOSTIC.md`](../../../../WRITER_PATH_DIAGNOSTIC.md)。仅使用此前 8 个 dev 源组、16 条双生版本；冻结模型、缓存及两个 writer，保留原 g 值，不训练、不评分 test。脚本为 `scripts/diagnose_cbf_writer_path.py`，两卡入口为 `scripts/run_cbf_writer_path_diagnostic.sh`，执行代码提交 `e1c522d`。

三种读出为原 BF16、仅 head FP32、完整模型 FP32；禁用 TF32，FP32 候选仍来自原有 BF16 缓存。配对 writer 另检查 C±sR，s=0/1/8/32，保持预设范数上限。这个操作需要同时知道两个上下文，属于不可部署诊断。s=0 真正共享相同记忆，s=1 精确保留原输出。

## 结果

| 配对 writer 读取配置 | 平均 NLL | 八选一准确率 | 正确更新对双生错配的 NLL 收益 |
|---|---:|---:|---:|
| 原 BF16 | 2.222859 | 12.5% | +0.007813 |
| 仅 head FP32 | 2.228050 | 12.5% | +0.001665 |
| 完整 FP32（上述参数值核验限制） | 2.229141 | 12.5% | −0.000018 |

普通 NLL writer 在三种配置下同样均为 12.5%。head FP32 明显改变微小 NLL 差，而没有改变准确率；这说明原来很小的 NLL 优势对输出精度敏感，不能单独当作可靠的内容记忆证据。不能由此声称所有失败都由 BF16 引起。

配对 writer 在 s=0/1/8/32、三种配置下的准确率均为 12.5%。完整 FP32 下查询 hidden 相对差异依次为 0、0.000103、0.000802、0.003195，表明放大确实改变读取信号；正确对错配的收益依次为 0、−0.000018、−0.000192、−0.000838，没有改善事实选择。该结果仅限固定网格及当前范数上限，不能排除其他写入结构。

逐层信号中位数显示：原候选相对差异约 **0.2376%**；配对 writer 在范数投影前/后均约 **0.1662%**。范数投影系数约 **0.498**，但前后相对差异几乎不变，因此不能把相对事实差异减小主要归因于这次投影。普通 writer 投影后约 **0.1516%**。

BF16 有效权重差异范数与 FP32 memory 差异范数之比，中位数约为配对 **10.24**、普通 **11.25**。这个比值包含舍入跳变，不能解释为语义信号被增强；它说明 BF16 合并产生的差异与原始微小差异不能简单等同。两版本的查询 hidden 和输出分布均有差别，因此链路有响应，但有数值差异不等于包含可泛化读取的颜色信息。

## 验证、资源与保存

两项 tiny 测试通过，覆盖投影、共享记忆、恒等、双生指标、原 forward 等价及 head FP32。真实 BF16 检查覆盖所有 16 条 dev 的无记忆、原候选及两种 writer，NLL 与准确率完全复现旧记录。两卡各完成 8 组，无 OOM；原 BF16+head FP32 每组平均 0.888 秒、最大 reserved 13.477 GiB；完整 FP32 每组 0.742 秒、19.611 GiB。两条任务 forward 数不同，耗时不用于比较精度性能。

聚合数值见 [`retrieved_summary.json`](retrieved_summary.json)，为此前已获准执行的远程日志读取输出的数值摘录，并非从完整逐组文件再做一次独立审计。完整日志、逐组记录和分片 summary 保存在 `/home/ctj/cbf_ttt_paired_fact_20260930/path_diagnostic_20261003/`。原始样本和逐组结果不上传 GitHub。
