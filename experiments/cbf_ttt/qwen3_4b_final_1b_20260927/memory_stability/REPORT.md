# 多 chunk 快记忆稳定性：完成报告

## 结论

在最终 Qwen3-4B / 1B checkpoint 的 4 个已看过的 pilot stable 场景中，原生 TTT 与 CBF 都随连续更新严重退化；改用 FP32 累积状态没有改善。**目前不能把退化仅归因于 CBF 的增量表示或 BF16 累加，也没有证据支持继续扩大遗忘控制器训练。** 每步清除避免了大部分退化，但这组数据上不写入的平均 NLL 更低，尚未证明有用的持续快记忆。

这是机制诊断，不能据此否定整个研究方向或宣称独立测试结论。训练覆盖不足是下一步待验证假设，不是本轮已证实的原因。

## 协议与执行

- 执行前固定方案：[MEMORY_STABILITY_PLAN.md](../../../../MEMORY_STABILITY_PLAN.md)。九路径、4 场景、每场景 7×4096 token，共 36 条轨迹。
- 只使用上一轮 pilot 中 stable 子集，不使用 confirm 或旧 writer test；因此均值不等同于上一轮全部四种场景均值。
- 每个边界独立克隆状态，评分后续 32-token query + 128-token answer。保留正常 KV；“不写入”只禁用快权重提交，不删除上下文。
- BF16 backbone/head/候选激活，TF32 关闭；FP32 路径仅改变状态累积精度，合成读取权重后转回 BF16。
- 2026-10-08 11:04:25–11:06:38（北京时间），两张 5090，流水线 133 秒。采集代码 `59fbba64badbc2964e3e46e7c8fd9d7f0404088a`。
- 20 项测试通过。原生与桥接在全部 28 个边界的 hidden、7 个 TTT 层有效权重字节哈希及 NLL 均相同；CBF/clear 的 24 个历史评分值重现误差为 0；骨干参数版本和基础权重哈希不变。

## 记忆与数值证据

- 原生实际快权重偏移 `||W−W0||/||W0||`，对 4 组×7 层平均，从首 chunk 的 0.4304% 增至第七 chunk 的 3.6742%；第七点最极端的单组单层达 23.4758%。CBF 有效偏移的平均值从 0.4304% 增至 3.7369%。平均值会掩盖层间差异，不能当作各层统一阈值。
- CBF 候选范数比例均值从 0.4310% 增至 0.8874%；每步清除的第七点存储 M 范数比例为 0.4015%。这些是相关诊断，不证明权重范数增长本身是唯一原因。
- 首 chunk 相同 BF16 输入上的 28 次逐层探针：CBF/原生相对 FP32 算术参考误差均值分别 0.2502% / 0.2377%；两候选相对差异均值 0.2169%，约 26.52% 元素不完全相等。差异存在，但替换运算/累积路径没有消除共同退化。
- 原生不可直接取得原始候选，相关字段为 null。FP32 完整 W 路径分别记录存储偏移与读取时 BF16 有效偏移，避免将两者混同。
- FP32 累积实验没有检验全模型、候选激活和读出的 FP32 精度；不能声称已排除所有数值问题。

## 下一步计划与停止条件

1. **先检查并缩小训练与推理的差距。** 当前 `configs/pretrain/qwen3_4b_1b.yaml` 为序列 6144、chunk 4096；训练实现分成两个块并只使用前一块候选，因此每条训练记录只覆盖一次影响后续 token 的更新。本轮推理有七次提交。需要先在相同短序列输入上检查训练/推理路径的等价范围和差异，再把长序列覆盖作为可检验假设。
2. **再做资源试跑。** 两张 32 GiB 卡此前 8192-token 全参数训练发生 OOM，不能直接启动长序列全参数大训练。优先验证只训练现有 TTT writer 参数、梯度检查点等可行方案；若采用冻结骨干方案，短/长对照必须同样冻结，明确它不同于此前全参数预训练。保持真实长上下文，不通过改变 chunk 大小替代多更新覆盖。
3. **预注册小预算短/长序列对照。** 同一 checkpoint、同样可训练参数集合、相同训练 token 预算与数据来源，比较 6144 与至少 3 个完整 chunk 的连续训练。开始前固定预算、优化器及选择规则，不根据 confirm 反复调参。现有 pilot 仅用于诊断；新独立来源做保留评估，并同时报告原生累积、每步清除、不写入。
4. **恢复选择性遗忘的门槛。** 只有长程累积不再崩溃，且在预设需要历史的任务中稳定优于不写入/清除，才重新检验局部遗忘 oracle 空间；通过后再构造多决策标签和训练控制器。若仍无写入收益，继续定位 writer/readout，不扩量掩盖问题。
