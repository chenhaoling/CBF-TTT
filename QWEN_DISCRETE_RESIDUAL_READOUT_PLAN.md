# Frozen discrete controller: Qwen residual-readout bridge

## Conditional release and claim boundary

This protocol is frozen while the fresh discrete confirmation is still on its
third development projection and before its test, lifecycle OOD outcomes or
any row in this bridge exists.  It may run only if both
`audit_qwen_discrete_cohort_confirmation_v1` and
`audit_qwen_discrete_cohort_ood_v1` pass their registered one-time gates.

The preceding controller uses Qwen-derived contextual geometry but evaluates a
`component_top1` similarity reader.  This bridge asks whether its frozen
cohort actions improve actual Qwen candidate likelihood and free generation
when the same decomposable low-rank memory is injected into the final hidden
state and read by the original LM head.  Native `ttt_conv`/`ttt_proj` weights
are loaded but do not write memory.  Their independently audited negative
content-binding result remains unchanged.  A pass supports a readable Qwen
residual fast-memory substrate; it is not a native dense-writer claim or an
automatic natural-text extraction claim.

## Fresh data and resource pilot

Use corpus seed `202610155`, new identifiers, templates and values, and the
same four registered lifecycle families: long session, distant revocation,
mixed reset/revoke and duplicate/no-op.  No identifier, value or source group
may occur in confirmation or lifecycle OOD data.  Every group has two twins
that differ in one initial anchor only.  Values are deterministically selected
to encode to exactly five Qwen tokens, enabling position-aligned residual
readout and full-sequence generation checks.

Before formal construction, run exactly eight groups per family (64 episodes)
with the full `{0, 0.5, 1}^3` action grid at the existing sparse decision
boundaries.  Record per-label wall time, prompt and candidate counts, token
length, and peak allocated/reserved memory.  Qwen prompt hidden states are
computed once per query; all 27 counterfactual residual states are scored in a
single vectorized LM-head operation.  The pilot can choose only the largest
formal group count that fits both RTX 5090 cards within 24 GiB allocated each
and an estimated four-hour wall-clock budget, from the ordered choices
`16/32/64` groups per family.  It cannot change actions, prompts, scales,
policies, metrics or success thresholds.  The selected count and raw resource
rows are committed before formal scoring.

## Frozen memory and Qwen read path

For every visible fact, construct a normalized key from its entity text and
five position-specific normalized value directions from the final Qwen3-4B
LM-head rows.  Keep components separately addressable by source record.  At a
query, top-1 key routing selects one component; its weighted five-token value
residual is added to the corresponding fresh-KV Qwen hidden states before the
unchanged LM head.  Use scale 8 as primary and report frozen sensitivity scales
4 and 16.  The query history never contains memory statements.

The controller features, contextual transforms, 27-class checkpoints and
threshold-free argmax are loaded from the audited confirmation.  No bridge
row trains or calibrates a controller.  For each projection seed, apply its
own frozen controller.  The actual-readout oracle evaluates the same 27 actions
using Qwen answer NLL, with ties within `1e-6` resolved by minimum removed mass
and then registered grid order.  Future blocks and answers never enter a
controller feature.

## Comparisons and causal controls

Replay identical writes and queries under all confirmation policies:

- retain all, global clear/half, and fixed two- and three-record windows;
- deterministic random actions and the reference-blind controller;
- continuous retention, independently snapped retention and the primary
  joint 27-class controller;
- explicit lifecycle physics, exact referenced-record deletion and the
  actual-Qwen 27-grid oracle.

Before policy comparison, verify content binding on every family with correct,
wrong-twin, zero and norm-matched sign-randomized memory.  Correct must improve
answer NLL over all three controls with source-group bootstrap 95% lower bounds
above zero.  Failure stops the bridge before a forgetting claim.

Report full-sequence candidate accuracy/NLL, greedy normalized exact match,
first-token accuracy, EOS rate, current/historical/anchor slices, every family,
action agreement with the actual-Qwen oracle, retention MAE, retained mass,
scale sensitivity, latency and peak memory.  Use 20,000 paired source-group
bootstrap draws.  Twins and their queries are never independent bootstrap
units.

## Registered formal gate

At primary scale 8, the frozen joint controller passes only if all hold:

1. candidate accuracy is at least 90% and greedy exact match at least 80%;
2. current and anchor accuracy are at least 95%, and historical accuracy at
   least 85%;
3. every lifecycle family has at least 85% candidate accuracy;
4. candidate-accuracy gain over the strongest non-oracle fixed or physics
   comparator is at least three points, with paired 95% lower bound above one
   point;
5. answer-NLL gain over that comparator has a 95% lower bound above zero;
6. every projection seed and lifecycle family has nonnegative accuracy gain;
7. the actual-Qwen oracle gap is at most five points;
8. the content-binding gate passes in every family;
9. scales 4 and 16 show no more than a five-point candidate-accuracy loss from
   scale 8 and no EOS-rate increase above five points;
10. every data, dependency, action, prompt, raw row, aggregate, bootstrap,
    resource and completion audit passes.

There is no second attempt on this corpus.  Failure is reported by content
control, policy, family, scale and projection seed and ends this exact-state
bridge.  A pass releases a separately preregistered natural explicit-lifecycle
evaluation; it does not unlock LoCoMo or RULER through synthetic results alone.
